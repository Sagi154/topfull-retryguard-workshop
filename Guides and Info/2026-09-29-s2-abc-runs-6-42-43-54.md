# S2 both-off runs 6, 42, 43, and 54, all services

600 s holds, both controllers off, `spawn_rate` 50. These four holds are not one series. Each has its own CPU table and its own user counts. Run 6 is Paper, frontend pinned at 4, sidecar request 90 m. Run 42 is Checkout-3, sidecar request 100 m with no CPU limit. Run 43 is Checkout-4, sidecar request 100 m with no CPU limit. Run 54 is Recs-3, sidecar request 90 m with no CPU limit. How the three signals are read: [2026-09-24-s2-both-off-abc-reading.md](2026-09-24-s2-both-off-abc-reading.md). The CPU tables: [2026-09-26-s2-cpu-limits-for-spread.md](2026-09-26-s2-cpu-limits-for-spread.md). Layout: [2026-09-27-s2-cpu-variant-handoff.md](2026-09-27-s2-cpu-variant-handoff.md) §Post-run analysis, the same sections as [2026-09-27-s2-checkout3-cpu-runs-39-42.md](2026-09-27-s2-checkout3-cpu-runs-39-42.md).

Counts are getproduct / postcheckout / getcart / postcart / emptycart. (a)/(b)/(c) and CPU mean / max are from `experiments/s2_both_off_abc.py` on these four folders. The other tables use the same Locust, inbound, CPU, and detector reads as the Checkout-3 guide.
